# 南科大棒垒球队公开账本与财务交接

这个文件夹用于维护球队日常收支资料和队费记录，让队员能查询消费，也让下一任财务能接着做。

公开消费记录在 [GitHub 原仓库](https://github.com/Lay-Yin/SUSTech-baseball-Softball-Team-Public-ledger)。原先由 Telegram 机器人识别截图并上传，现在可以直接把图片交给 AI 代理，在本地完成识别、归档和 CSV 更新。代理的具体操作规则见 [AGENTS.md](AGENTS.md)。

## 队员如何查账、交材料

查看 [公开消费账本](https://github.com/Lay-Yin/SUSTech-baseball-Softball-Team-Public-ledger/blob/main/public-ledger.csv)，按记录时间、商家、货品和金额找到对应消费；历史凭证在 [截图目录](https://github.com/Lay-Yin/SUSTech-baseball-Softball-Team-Public-ledger/tree/main/order_screenshots)。旧记录不一定都有完整凭证对应关系，疑问可向现任财务提供具体账目核实。

报销或补记消费时，请把这些信息一起交给财务：

- 清晰的订单或付款截图，尽量包含商家、货品、实际支付金额及付款状态。
- 这笔支出的球队用途、垫付人，以及是否已经报销或记过账。
- 如有多笔订单、部分退款、运费或仅报销一部分，请说明具体范围。

提交前可遮住与核账无关的手机号、地址和账号，保留交易信息。记入消费账本不代表报销款已经支付，到账情况仍需向财务核对。

队费金额、收款方式和截止时间以当学期球队通知为准。转账后向财务说明姓名和学期，新队员同时补充背号。

## 财务平时做什么

财务工作分为两部分：管理球队收入与支出，以及收取队费、更新名单。从 2025 年秋季起，队费表按学期记录缴纳情况，也兼作带背号的队员名单。

学期初核对老队员并收队费，新队员加入后及时跟进。收到付款凭证后确认实际到账，再更新对应学期。遇到消费就及时整理票据并入账；定期将凭证、账目、实际收付款和待报销事项对一遍。

## 文件在哪里

当前本地结构如下；截图目录与辅助记录在首次需要时创建：

```text
财务工作目录/
├─ README.md                     给队员和交接财务的说明
├─ AGENTS.md                     给 AI 代理的维护规则
├─ 财务工作.txt                  原交接说明
└─ sustech/
   ├─ public-ledger.csv          公开消费账本
   ├─ sustech submarine.csv      内部队费名单及背号
   ├─ order_screenshots/         公开凭证目录（按需创建）
   │  └─ 凭证索引.md            新账目与截图的对应关系（按需创建）
   ├─ 待核实事项.md              未解决事项，内部使用（按需创建）
   ├─ bill_workflow_docker.py    旧 Telegram 机器人
   ├─ ocr.py                    旧识别脚本
   ├─ Dockerfile
   ├─ requirements.txt
   └─ .env                      旧部署配置，勿公开
```

GitHub 原仓库的 `public-ledger.csv`、`order_screenshots/` 和网页 `index.html` 直接位于仓库根目录；本地 `sustech/` 是存放资料的目录名。向原仓库同步时，按原仓库结构放置文件。

## 用 AI 处理一批截图

在能访问此文件夹的代理中发送图片，可以直接这样说：

> 按 AGENTS.md 处理这些球队消费截图：读取实付金额，检查是否重复，把截图存入 order_screenshots，更新凭证索引，并追加 public-ledger.csv。信息明确的直接保存，有疑问的单独列出来。最后告诉我新增笔数、合计和文件位置。

代理应完成“读图核对 → 查重 → 保存凭证及索引 → 追加 CSV → 复核”，一笔订单只记一次。一个订单有多件商品但只有总价时，按整单记账；同一笔订单的多个截图用于佐证，不重复累计。需要纠正识别文字时，仍保留截图。

结果中应能看到新增消费笔数、本批金额合计、保存位置和待核实问题。金额看不清、疑似重复或不能判断付款状态时，补充对应信息即可。不要把待核实项目当作已入账。

只想先识别、不写账时明确说“只整理待核对清单”。需要同步 GitHub 时明确说“将本次公开账本和凭证同步到原仓库”。本地保存与线上发布是两件事。

## 两张表怎么理解

### 消费账本

`public-ledger.csv` 保留原来的四列：

| 字段 | 含义及填写方式 |
| --- | --- |
| 记录时间 | 新增记录默认填北京时间录入时间；历史部分只有日期，按原样保留 |
| 商家 | 店铺或收款方；确实不明可留空 |
| 货品 | 商品或球队用途，例如球场灯安装、比赛用球 |
| 金额 | 实际消费金额；新增人民币记录统一如 `¥120.00` |

交易日期另在凭证索引说明；需要按交易日期记账时明确告诉代理。不要把商品单价、优惠前总价和实付款混用，也不要在表尾加合计行。使用表格软件手工保存时，保留 UTF-8 CSV 格式和四列表头。

现有网页只统计“总消费金额”，并不能代表球队余额。它也不正确处理负号和带英文逗号的字段，因此收入、队费收入、退款暂不能直接混进这张表。此类材料先内部留存并列入待核实事项，由财务确定收入记录方式；如要建立完整收支账，需要一起调整账本结构和网页统计。

### 队费名单

`sustech submarine.csv` 当前包含姓名、2026 春季学期、2025 秋季学期和背号。`√` 表示该学期已登记缴费；空白表示尚未登记为已缴，需要核实，不能直接判定欠费。新学期增加一列，保留历史；新队员增加一行。

可这样交给代理：

> 已核实某某的 2026 秋季队费到账，请更新对应学期。如果该学期列还没有，请新增并保留历史记录。背号为 XX。

名单不记录实收金额，仅凭勾选人数无法计算准确收入。财务仍需保存实际收款依据，特别是减免、补缴或金额不同的情况。名单默认仅供内部使用，不随消费账本上传公开仓库。
